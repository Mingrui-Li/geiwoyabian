# 《给我压扁！》精简路线图

目标不变：完成一款有趣、解压、UI精致、可正式上线的抖音小游戏，不降级为MVP。

此前把UI拆成十多个任务、为每组组件重复建立checklist和证据，已经造成明显的时间与token浪费。从2026-09-01起，剩余工作只保留两个工作流。

## 1. GWP-017：完整Figma UI

直接使用已经完成的视觉基准、Foundations和组件，组装并打磨整套玩家界面。一个工作流内完成，不再拆成HUD、线框、高保真、异常状态、适配、原型、审计和交接等独立任务。

最终只看四件事：

- 玩家实际会看到的界面是否齐全。
- 整体视觉是否好看、统一、符合“充气贴纸工坊”。
- 游戏操作、主要流程和必要状态是否清楚。
- 用户是否确认可以照此进入Cocos开发。

允许同一页面承载多个状态，不强制把旧`SCREEN_SPEC.md`的24类条目做成24张独立画板。旧规格仅作为防遗漏参考。

## 2. GWP-030：完整Cocos小游戏开发

GWP-017通过用户确认后，直接进入完整游戏开发。初始化、架构、核心玩法、UI实现、完整内容、抖音能力、性能和发布验收都属于同一工作流，可以跨多个对话持续推进，不再为每个阶段创建任务门禁。

完整范围仍以`docs/PROJECT_PLAN.md`为准：5个主题、75关、至少50件物品、4种模式，以及图鉴、外观、成就、设置、分享和克制的激励广告。排行榜、公会、家园、剧情和多人对战继续永久排除。

## 唯一门禁

在GWP-017完整UI得到用户确认前，不进入正式Cocos开发。除此之外，不再设置中间文档门禁。
