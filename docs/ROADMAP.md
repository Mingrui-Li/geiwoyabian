# 完整版本路线图：设计先行

本路线图的终点是可正式上线的完整 v1.0。UI/UX 与游戏画面不是开发后的装饰层，而是所有正式工程工作的输入。因此顺序固定为：

```text
产品与界面规格
→ gpt-image-2 视觉探索与资产基准
→ Figma设计系统
→ Figma完整24类界面、状态、原型、适配与评审冻结
→ Cocos工程和设计组件映射
→ 核心玩法、完整内容、平台能力与发布打磨
```

## 硬门禁

在 `GWP-026：Figma设计冻结与开发交接` 变为 `DONE` 前：

- 不得初始化或合入正式 Cocos 工程。
- 不得实现正式场景、HUD、导航、弹窗或游戏流程。
- 不得用灰盒界面替代正式设计决定布局和组件结构。
- 已经存在的实验性 Cocos 分支只能保留，不能合入 `main`；设计冻结后再评估复用。

按单人全职开发粗估为 18–26 周。设计阶段占用真实排期，不能压缩成一个笼统任务。

## D0：产品界面规格锁定（2–4 天）

### 交付

- [ ] 24类正式屏幕的信息、主要动作、进入/退出路径和边界状态
- [ ] 首次体验、闯关、自由解压、今日订单、连续压、图鉴、外观和分享的用户流程
- [ ] 游戏HUD的信息优先级、手指热区和安全区
- [ ] 每个屏幕的真实中文文案和数据样例
- [ ] 设计组件清单、视觉资产清单和验收矩阵

### 闸门

- [ ] 每个功能都有明确界面承载，不存在“开发时再想”
- [ ] 所有流程无死路，返回、暂停、错误和恢复路径完整
- [ ] 用户确认界面范围与整体流程后才能进入视觉探索

## D1：gpt-image-2视觉方向与资产基准（4–7 天）

### 交付

- [ ] 2–3套完整视觉方向，而不是零散物品图
- [ ] 每套包含主入口、游戏画面、结算页的关键视觉示意
- [ ] 液压机、传送带、代表物品、背景、面板材质和装饰母题
- [ ] 唯一入选方向的风格基准图、色彩、轮廓、光向和材质规则
- [ ] 批准素材与候选素材分离的资产清单

### 闸门

- [ ] UI、游戏舞台和物品属于同一个视觉世界
- [ ] 缩到目标手机尺寸后仍清晰可读
- [ ] 用户选定唯一方向后才能建立Figma变量与组件

## D2：Figma文件、变量、样式与结构（5–8 天）

### 交付

- [ ] 检查目标共享文件、Page、现有库和编辑边界
- [ ] 在指定Page的 `GWP_给我压扁` Section内建立项目设计区
- [ ] 建立可跨窗口恢复的Figma状态台账，记录file key、Section ID、节点ID和验证状态
- [ ] 锁定token与组件v1清单并输出gap analysis
- [ ] 建立primitive与semantic变量、明确scope与code syntax
- [ ] 建立字体、字号、行高、阴影和效果样式
- [ ] 建立Cover、Foundations、Components、Flows、Screens、Dev Handoff等一级Frame
- [ ] 为基础页生成截图并完成结构验证

### 闸门

- [ ] 变量先于组件，所有scope和code syntax完整
- [ ] 没有用硬编码颜色、间距或圆角替代已有token
- [ ] 每次Figma写入均返回节点ID并同步状态台账
- [ ] Foundations截图和metadata检查通过

## D3：Figma组件系统（8–14 天）

组件必须逐个创建和验证，不能一次批量生成整个设计系统。

### 基础组件

- [ ] 主/次/危险按钮、图标按钮
- [ ] 顶部栏、底部导航、标签和分页
- [ ] 状态胶囊、徽章、进度、星级和Toast
- [ ] 通用面板、弹窗、奖励弹窗、加载和错误状态

### 内容与游戏组件

- [ ] 模式卡、主题卡、关卡卡、图鉴格、物品详情卡、外观卡
- [ ] 压力条、连击徽章、关卡进度、结果标签和高塔结算组件
- [ ] HUD容器、安全区、暂停与分享预览组件

### 闸门

- [ ] 每个组件使用Auto Layout、变量绑定和可控变体
- [ ] 默认、按下、禁用、选中及适用的锁定/完成/加载/错误状态齐全
- [ ] 每个组件单独完成metadata与screenshot验证
- [ ] 无重复组件、无未命名节点、无超过30组合的失控变体矩阵

## D4：Figma完整UI/UX、原型与设计冻结（12–20 天）

### 核心界面

- [ ] 启动加载、首次直接按压教学、主入口、模式选择
- [ ] 主题选择、关卡选择、游戏HUD、暂停
- [ ] 高塔粉碎、关卡结果、解锁奖励

### 长期与系统界面

- [ ] 图鉴、物品详情、自由解压、今日订单、连续压
- [ ] 外观、成就、设置、录屏/分享预览
- [ ] 广告确认/奖励、通用确认、断网、错误和恢复状态

### 设计完成项

- [ ] 所有界面使用设计系统实例组装，不是散落的硬编码Frame
- [ ] 360×800主画板及375×812、393×873适配画板
- [ ] 完整可点击原型走通首次体验、闯关、图鉴、模式和分享
- [ ] 所有加载、空、锁定、完成、错误和恢复状态
- [ ] 动效意图、时长、缓动和层级说明
- [ ] Dev Handoff精确节点、截图和资产导出清单

### 设计冻结闸门

- [ ] 24类界面逐屏结构与截图验证通过
- [ ] 组件、变量、字体、触控热区、对比度和安全区审计通过
- [ ] 用户完整审阅并确认核心视觉与流程
- [ ] `GWP-026`完成节点登记、Figma链接和开发交接

## C0：Cocos工程与设计映射（5–8 天）

仅在D4设计冻结后开始。

### 交付

- [ ] 初始化Cocos Creator 3.8.7+ TypeScript竖屏工程
- [ ] 将Figma token映射为Cocos颜色、字体、间距和动效常量
- [ ] 建立Figma组件到Cocos prefab/component的对应表
- [ ] 建立平台适配、状态机、配置、对象池和资源分包骨架
- [ ] 实现正式导航壳和首批基础组件，并与Figma截图对照

### 闸门

- [ ] 不存在由开发者临时发明的正式UI样式
- [ ] 首批组件和框架在三种屏幕比例下匹配Figma
- [ ] 编辑器预览和浏览器构建通过

## C1：核心玩法与正式30秒闭环（2–3 周）

### 交付

- [ ] 液压机输入、压力、压缩率和四档判定
- [ ] 脆性、弹性、爆浆三种首批正式物品
- [ ] 形变、停顿、震屏、粒子、声音和震动反馈
- [ ] 装载、按压、结果、入塔、下一件和倒塔闭环
- [ ] 使用Figma正式HUD、教学、高塔与结果界面

### 闸门

- [ ] 新玩家5秒内完成第一次按压
- [ ] 至少4/5测试者愿意再压一件
- [ ] 视觉、交互和界面都达到设计稿而非灰盒水平
- [ ] Cocos截图与Figma核心界面逐屏对照通过

## C2：完整系统与内容生产（7–10 周）

- [ ] 5个主题、75个关卡、至少50件物品
- [ ] 压扁之旅、自由解压、今日订单和连续压
- [ ] 图鉴、10套液压机外观、5套背景、30个趣味成就
- [ ] 本地存档、迁移、设置和异常恢复
- [ ] 所有正式界面、状态和动效按Figma完整实现
- [ ] 内容按主题分包和按需加载

## C3：抖音能力、商业化与发布打磨（3–5 周）

- [ ] 自动录屏、精彩片段、分享预览和发布
- [ ] 克制的激励广告与奖励一致性
- [ ] 埋点、性能、低端机、多屏适配和30分钟稳定性
- [ ] 全量Figma/Cocos视觉回归与真机触控回归
- [ ] 审核、隐私、合规、图标、简介和首批传播素材

## 上线后原则

新增内容继续服务于压扁手感、物品惊喜和短时解压；不扩展排行榜、公会、家园、剧情或多人系统。任何新增正式界面仍必须先进入Figma设计与评审，再进入Cocos实现。
