# 完整版本路线图

本路线图的终点是可正式上线的完整 v1.0，不是 MVP。灰盒、垂直切片和内部版本只是依次验证玩法、视觉与生产效率的阶段。按单人全职开发粗估为 14–20 周；这是排产参考，不是以日期牺牲质量的承诺。

## P0：工程基线与产品锁定（1–2 天）

### 交付

- [ ] 创建 Cocos Creator 3.8.7+ TypeScript 项目
- [ ] 设置竖屏、参考分辨率和安全区策略
- [ ] 建立 `GameFlow`、配置、平台适配、音频与对象池目录
- [ ] 建立可在浏览器运行的 `NoopPlatformAdapter`
- [ ] 将 5 个主题、4 种模式和永久排除项写入项目配置或文档基线

### 验收

- [ ] 编辑器预览和浏览器构建成功
- [ ] 核心玩法代码不出现直接的 `tt.*` 调用
- [ ] 后续开发不会把“内部原型”误认为最终产品范围

## P1：核心手感灰盒（3–5 天）

此阶段允许使用纯色块和临时音效，只验证按压是否有趣，不代表正式 UI。

### 交付

- [ ] 长按下降、接触、增压、松开和回升
- [ ] 统一压缩率与四档结果判定
- [ ] 三个灰盒原型：脆性纸箱、弹性橡皮鸭、爆浆纸杯
- [ ] 基础形变、震屏、停顿、粒子和临时音效
- [ ] 连续装载 10 件物品

### 感觉闸门

- [ ] 新测试者无需解释能在 5 秒内完成第一次按压
- [ ] 至少 4/5 测试者愿意主动再压一件
- [ ] 连续压 10 件时没有状态卡死或明显输入延迟
- [ ] 关闭得分和奖励后，玩法仍有重复欲望

未通过时继续迭代手感，但不取消完整 UI 和完整内容目标。

## P2：正式视觉方向与 Figma 设计系统（7–10 天）

严格执行“gpt-image-2 → Figma MCP”的顺序。

### 交付

- [ ] 生成 2–3 套视觉探索，确定唯一风格基准
- [ ] 生成液压机、示例物品、背景、纹理和装饰母题
- [ ] 通过 Figma MCP 在指定共享 Page 的 `GWP_给我压扁` Section 内建立正式设计区
- [ ] 建立颜色、字体、间距、圆角、描边、阴影和动效变量
- [ ] 建立按钮、卡片、导航、进度、弹窗、奖励和 HUD 组件及完整状态
- [ ] 完成全局信息架构与关键用户流程
- [ ] 完成核心屏幕的高保真稿与可点击原型

### 设计闸门

- [ ] 风格在游戏画面、HUD 和弹窗之间保持一致
- [ ] 主操作、返回、暂停和奖励入口无需解释即可找到
- [ ] 360×800、375×812、393×873 三种竖屏画板均无布局破坏
- [ ] 按下、禁用、选中、锁定、加载、错误和解锁状态齐全
- [ ] Figma 中不存在依赖生成图片文字的 UI

## P3：正式 30 秒垂直切片（10–14 天）

从这一阶段开始，所有正式界面必须从精确 Figma 节点实现，不允许在 Cocos 中临场设计。

### 交付

- [ ] 正式液压机、传送带、背景和 6 件物品
- [ ] 按 Figma 实现启动、首次教学、游戏 HUD、高塔结算和关卡结果
- [ ] 连击的三档视听升级
- [ ] 方块入塔与一个完整主题倒塔结尾
- [ ] 30 秒无需解说的录屏素材
- [ ] Figma 截图与 Cocos 真机截图逐屏对照

### 验收

- [ ] 静音观看仍能看懂“操作—结果—高潮”
- [ ] 从启动到首次爽点不超过 10 秒
- [ ] 一段录屏至少包含一个预期满足和一个意外反转
- [ ] 核心 UI 达到 Figma 视觉与交互意图，不是功能占位版
- [ ] 在目标抖音真机上完成一次完整流程

## P4：完整系统骨架与全流程 UI（10–14 天）

### 交付

- [ ] 关卡、主题、物品、奖励和解锁全部配置化
- [ ] 压扁之旅、自由解压、今日订单、连续压四种模式的完整流程
- [ ] 本地存档、版本迁移、设置和异常恢复
- [ ] Figma 完成全部正式屏幕、边界状态和开发标注
- [ ] Cocos 完成主入口、主题/关卡选择、图鉴、模式页、皮肤、设置、分享预览等全部 UI
- [ ] UI 动效、转场、点击和反馈音效形成统一语言

### 验收

- [ ] 从任意二级页面都能清晰返回且没有流程死路
- [ ] 主要流程可用单手拇指完成
- [ ] 新物品和新关卡只需配置与资产即可接入
- [ ] 每个正式屏幕都完成 Figma/Cocos 对照检查
- [ ] 删除存档、升级存档和异常退出后可安全恢复

## P5：完整内容生产（4–6 周）

### 交付

- [ ] 5 个主题工坊的背景、机器装饰、环境音层和倒塔结尾
- [ ] 至少 50 件正式物品，覆盖五类材质与组合行为
- [ ] 75 个手工编排关卡
- [ ] 每个主题 3 个节奏单元和 3 个压轴关
- [ ] 烦恼图鉴的三类结果记录
- [ ] 10 套液压机外观、5 套工坊背景和 30 个趣味成就

### 验收

- [ ] 五个主题在材质、节奏、声音和笑点上有明显区别
- [ ] 完整游玩 75 关无阻塞、重复关卡或明显难度断层
- [ ] 任何连续 5 关都至少出现一次新组合或视觉反转
- [ ] 同屏生成资产已经过 Figma 统一构图与视觉检查
- [ ] 内容包按主题加载，无无引用资源进入主包

## P6：留存、分享与商业化闭环（7–10 天）

### 交付

- [ ] 今日订单的本地固定种子与完成记录
- [ ] 连续压的本地最佳连击
- [ ] 精彩片段挑选、自动录屏、分享预览和发布入口
- [ ] 关卡、模式、图鉴和外观相关埋点
- [ ] 克制的激励广告与自然关卡间隔商业化

### 验收

- [ ] 分享和广告成功、取消、失败都不会阻塞游戏
- [ ] 奖励文案与实际奖励完全一致
- [ ] 录屏 15–30 秒内能展示操作、反转和倒塔高潮
- [ ] 广告不会打断连续按压或强迫玩家观看才能游玩基础内容

## P7：性能、适配、审核与打磨（2–3 周）

### 交付

- [ ] 图集、纹理压缩、对象池、主题分包和按需加载
- [ ] 低端 Android 与多种屏幕比例真机测试
- [ ] 全量 UI 视觉回归、触控回归和动效回归
- [ ] 音效混音、震动强度、色彩和可读性打磨
- [ ] 审核素材、图标、简介、隐私与合规配置
- [ ] 首批 10–20 条玩法素材脚本

### 上线闸门

- [ ] 首包目标不超过 4MB
- [ ] 核心按压过程目标 30 FPS 以上，无持续严重卡顿
- [ ] 连续游玩 30 分钟无明显内存持续增长
- [ ] 75 关、4 种模式、图鉴、外观、设置、录屏分享和广告完成全量真机回归
- [ ] 所有正式屏幕与 Figma 基准完成最终对照
- [ ] 至少进行两轮外部小样本观察测试并处理高频问题

## 上线后前两周优先回答

1. 玩家是否在 10 秒内获得第一次爽点？
2. 哪类材质、哪种结果和哪个主题最容易促成下一局？
3. 四种模式分别承担了多长的游玩时间？
4. UI 中哪些入口存在误触、忽略或理解偏差？
5. 哪种自动录屏结构最容易促成预览和分享？

上线后的新增内容仍必须服务于压扁手感、物品惊喜和短时解压，不扩展排行榜、公会、家园、剧情或多人系统。
