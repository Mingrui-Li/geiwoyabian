# 《给我压扁！》整体产品与开发规划

版本：0.3
状态：立项基线
目标平台：抖音小游戏
团队：单人开发（OPC）

本规划面向可正式上线的完整 v1.0。UI/UX与视觉设计是工程输入：必须先完成gpt-image-2视觉基准、Figma设计系统、24类正式界面、全部状态、适配、原型和Dev Handoff，再开始Cocos工程与玩法实现。后续可玩闭环用于验证设计与手感，但不能倒置设计和开发顺序。

## 1. 产品定义

### 一句话体验

玩家长按控制液压机，把闹钟、未读消息、缠绕耳机等“日常烦恼”压成方块，并在结算时一击推倒由它们组成的烦恼高塔。

### 玩家幻想

“现实里处理不了的麻烦，在这里可以被我压得服服帖帖。”

### 核心承诺

1. 五秒看懂：不读教程也知道长按会发生什么。
2. 每次都有反馈：位移、形变、声音、震动、粒子和停顿同时服务于按压手感。
3. 失误也好玩：失败制造回弹、爆浆或意外揭示，不用严厉惩罚打断解压感。
4. 一局像一条短视频：过程逐步升级，结尾有可分享的高塔粉碎高潮。

### 非目标

- 不做写实液压机模拟器。
- 不做复杂软体物理或大量 3D 资产。
- 现在及以后均不做排行榜、PvP、公会、家园、剧情和多人对战。
- 不做复杂角色养成、装备战力或重度数值成长。
- 不以插广告次数作为产品设计驱动力。
- 不允许玩法依赖用户输入自由文本，避免内容审核和隐私负担。

## 2. 目标用户与使用场景

### 核心用户

- 想用 1–3 分钟换取即时爽感的泛用户。
- 喜欢整理、破坏、ASMR、意外反转类短视频的用户。
- 不愿学习复杂规则，但愿意追求“完美一下”的轻度玩家。

### 典型场景

- 通勤或排队时单手游玩。
- 工作学习间隙释放烦躁。
- 刷到录屏后立即进入，先玩后理解。

## 3. 核心玩法

### 单件物品循环（约 4–8 秒）

1. 传送带送入物品，并用动作暗示其材质。
2. 玩家长按，压头下降；接触后压力与形变开始增长。
3. 玩家在判断合适时松手。
4. 系统根据最终压缩率给出结果。
5. 物品成为方块、发生滑稽事故，或弹回后被传送带送走。
6. 结果方块进入高塔，下一个物品出现。

### 判定

| 结果 | 条件 | 体验反馈 | 作用 |
|---|---|---|---|
| 完美 | 停在理想压缩区间 | 短暂停顿、低频重击、金色轮廓、方块严丝合缝 | 增加连击与高塔稳定度 |
| 合格 | 偏离理想区间但未越界 | 普通压缩声、轻微歪斜 | 正常得分，不中断流程 |
| 欠压 | 松手过早 | 物品慢慢回弹或尴尬滑走 | 连击中断，但不结束关卡 |
| 过压 | 超过破裂阈值 | 爆浆、弹簧、小物件飞出等喜剧事故 | 连击中断，生成不同回放素材 |

完整版本不使用传统“生命值”。玩家可以完成一局，只是高塔形态、得分与结尾效果不同。

### 压力信息设计

首个教学关显示清晰压力条和理想区间。之后逐步降低提示强度，让玩家更多观察物品形变、抖动和声音。无障碍选项可永久显示压力条。

### 连击

- 连续完美会提升传送带节奏，并逐级增强音效与背景灯光。
- 第 3、6、10 连击触发短促高潮，不弹窗、不夺走操作权。
- 连击只是爽感放大器，不直接决定能否过关。

## 4. 物品系统

所有物品使用统一行为模型，通过配置组合差异；禁止为每个物品创建一套独立玩法脚本。

### 基础材质原型

| 原型 | 特征 | 示例 | 实现方式 |
|---|---|---|---|
| 脆性 | 先抵抗，突然碎裂 | 闹钟、饼干盒 | 分段缩放 + 裂纹遮罩 + 碎片粒子 |
| 弹性 | 松手后明显回弹 | 枕头、橡皮鸭 | Tween 回弹 + 挤压音高变化 |
| 爆浆 | 越压越鼓，过压喷溅 | 番茄、奶茶杯 | 轮廓膨胀 + 喷溅序列帧 |
| 嵌套 | 压开后出现意外内容 | 快递盒、文件夹 | 状态换图 + 弹出子物件 |
| 不稳定 | 理想区间移动或短暂出现 | 震动手机、爆米花桶 | 配置化区间偏移 + 预警动作 |

### v1.0 内容主题

完整版本包含 5 个主题工坊、75 个精心编排的关卡和至少 50 件可压物品。主题不是剧情章节，而是改变材质组合、背景氛围、音效与喜剧表达的内容集合。

| 主题工坊 | 代表物品 | 体验重点 | 规模 |
|---|---|---|---:|
| 桌面乱成团 | 闹钟、耳机、咖啡杯、键盘、快递盒 | 建立规则与基础材质认知 | 15 关 / 10 件 |
| 厨房别炸锅 | 泡面桶、番茄酱包、吐司机、果冻、汽水罐 | 爆浆、膨胀和连续反应 | 15 关 / 10 件 |
| 通勤挤一挤 | 公文包、雨伞、纸票、折叠车、行李箱 | 弹性、嵌套和空间错觉 | 15 关 / 10 件 |
| 办公全压平 | 文件山、打印机、订书机、会议牌、旋转椅 | 不稳定区间和节奏组合 | 15 关 / 10 件 |
| 奇怪解压所 | 月亮枕头、云朵罐、迷你火山、尖叫盒、无限纸箱 | 规则反转与终局视觉高潮 | 15 关 / 10 件 |

每个主题至少包含：2 件脆性、2 件弹性、2 件爆浆、2 件嵌套、1 件不稳定和1件主题压轴物品。部分物品可以组合多种原型，但必须能通过统一配置和组合式效果实现。

Figma设计冻结后的首个正式可玩闭环使用纸箱、橡皮鸭和纸杯，分别验证脆性、弹性和爆浆反馈；即使内容较少，也必须使用Figma冻结后的正式HUD、教学、结算和视觉资产，不允许回退成决定界面结构的灰盒。

### 建议配置模型

```ts
type ItemArchetype = 'brittle' | 'elastic' | 'squishy' | 'nested' | 'unstable';

interface PressableItemConfig {
  id: string;
  archetype: ItemArchetype;
  resistance: number;
  idealCompression: readonly [number, number];
  ruptureCompression: number;
  rebound: number;
  deformationProfile: string;
  effectProfile: string;
  scoreValue: number;
}
```

## 5. 一局的结构

### 主关卡

- 每关 8–12 件物品。
- 目标时长 60–120 秒。
- 前两件建立节奏，中段引入材质变化，最后一件保证视觉高潮。
- 完成后立即进入高塔结算，不插入多层奖励弹窗。

完整版本共 75 关。每 5 关形成一个小节奏单元：教学组合、熟练组合、速度变化、规则混合、主题压轴。关卡不依赖剧情文本，但通过物品出场、机器状态和结果笑点形成清晰的体验起伏。

### 高塔结算

本局合格和完美物品成为方块，按表现形成整齐或歪斜的高塔。玩家长按蓄力并释放冲击锤：

- 塔越整齐，倒塌越连贯，得分越高。
- 事故物品会在倒塌时触发二次笑点。
- 系统保留 3–5 个精彩片段，与倒塔结尾拼成分享候选视频。

### 完整游戏模式

1. **压扁之旅**：75 个手工关卡，是主要内容与解锁路径。
2. **自由解压**：从图鉴选择已解锁物品，不计失败、不限次数，自由调整传送速度和提示强度。
3. **今日订单**：每天由固定种子生成一组 12 件物品和一个轻量规则变化，只有个人完成记录，不设排行榜。
4. **连续压**：物品节奏逐渐加快，记录本地个人最佳连击；纯可选，不阻碍主线解锁。

### 完整元进度

- 关卡星级解锁后续关卡、主题和自由解压物品。
- “烦恼图鉴”记录至少 50 件物品的完美、欠压、过压结果和材质提示。
- 10 套液压机外观和 5 套工坊背景通过关卡与图鉴完成度获得，只改变表现，不售卖数值优势。
- 30 个本地趣味成就引导玩家发现特殊结果，例如连续回弹、嵌套连锁或完美高塔。
- 每个主题完成后解锁一个独特的高塔粉碎结尾。

这些系统共同构成完整游戏的回访理由，但不引入家园、角色养成、排行榜或社交压力。

## 6. 首次体验

1. 启动后直接看到一个不断震动的闹钟，不先展示复杂首页。
2. 屏幕中央提示“按住，压扁它”。
3. 玩家第一次按住时进入慢速教学，压力条始终可见。
4. 无论成绩如何都产生明显反馈；第一次过压应当好笑而非挫败。
5. 完成三个物品后才展示关卡、图鉴与皮肤入口。

目标：从首次可交互到第一次爽点不超过 10 秒。

## 7. 视觉与声音

### 视觉方向

- 关键词：软陶玩具、圆角工业设备、夸张材质、明亮、不写实。
- 主色：工业黄 `#FFC83D`、压力红 `#FF5D55`、深墨蓝 `#243145`。
- 辅色：薄荷绿 `#63D7B0`、奶油白 `#FFF4DE`。
- 游戏内文字由引擎渲染，禁止把文字生成在图片中。
- UI 必须具有完整设计系统、清晰的信息层级和精致的动效反馈，不以“轻量游戏”为理由降低界面质量。
- gpt-image-2 负责关键视觉资产；Figma MCP负责页面构图、设计系统、组件状态、交互流程和多尺寸适配；Cocos严格依据Figma实现。

### UI/UX 完整范围

正式版本至少包含启动/首玩、主入口、主题与关卡选择、游戏 HUD、暂停、高塔结算、关卡结果、图鉴、物品详情、自由解压、今日订单、连续压、液压机外观、设置、解锁奖励和分享预览等完整界面。

设计原则：

- 一屏一个主要动作，主按钮无需阅读就能辨认优先级。
- 所有触控热区不少于 44×44 逻辑设计单位（@2x 资产对应 88×88 像素），且避开抖音胶囊区和设备安全区。
- 按下、禁用、选中、解锁、加载和错误状态都必须有正式设计。
- 核心游戏 HUD 不遮挡物品形变、高塔和玩家手指区域。
- 动效服务于状态变化：压下、获得、解锁、切换、结算都应有明确的起止反馈。
- 详细流程以 `docs/UI_DESIGN_WORKFLOW.md` 为准，Figma 文件是正式 UI 的唯一设计源。

### 声音方向

手感优先级为：接触声 > 持续受压声 > 释放声 > 结果声 > 环境音乐。

完整版本至少需要：

- 液压机启动、下降、停止、回升
- 低频完美重击
- 三类材质受压声
- 回弹、碎裂、喷溅
- 连击三档提示
- 高塔倒塌与最终冲击
- 5 个主题的低存在感环境层
- UI 点击、切换、解锁、奖励和错误提示音
- 50 件物品通过材质组合和轻微音高变化形成可辨识差异

背景音乐应低存在感，避免盖住材质反馈。音效需要随压力、速度轻微改变音高，减少重复感。

## 8. 技术方案

### 技术栈

- Cocos Creator 3.8.7+
- TypeScript
- 2D Sprite、Mask、Particle2D、Tween、AnimationClip
- 抖音小游戏平台适配层
- 完整 v1.0 本地存档，无玩法服务端

选择 3.8.7+ 是因为抖音小游戏当前从该版本起提供默认 Cocos 引擎插件支持。完整版本使用分包按主题加载，主包按不超过 4MB 设计，只包含首次互动、通用UI和第一个主题的必要入口资源。

### 场景策略

尽量使用一个常驻主场景，通过 UI 层与游戏状态切换，避免多个重场景造成加载和状态管理复杂度。

建议节点层次：

```text
GameRoot
├── BackgroundLayer
├── MachineLayer
│   ├── PressHead
│   ├── PressableItemSlot
│   └── Conveyor
├── EffectsLayer
├── TowerLayer
├── HudLayer
└── ModalLayer
```

### 主要模块

| 模块 | 职责 |
|---|---|
| GameFlow | 明确管理引导、装载、按压、结算、高塔等状态 |
| PressController | 将按住/松开输入转换为压头位置、速度与压力 |
| PressableItem | 读取配置并输出形变进度与材质事件 |
| ResultResolver | 统一计算完美、合格、欠压、过压 |
| FeedbackDirector | 震屏、停顿、粒子、音效、震动的编排 |
| ConveyorController | 物品进出场与节奏控制 |
| TowerController | 方块堆叠和结算倒塌 |
| HighlightBuffer | 记录可重演的关键状态，不录制整局游戏逻辑 |
| SaveService | 本地进度、设置与图鉴 |
| PlatformAdapter | 录屏、分享、广告、震动、生命周期 |
| Analytics | 统一事件名和参数，本地实现可为空操作 |

### 状态流

```text
Boot → Tutorial/Ready → LoadingItem → Pressing → Resolving
                                      ↑             ↓
                                  NextItem ← Stacking
                                                   ↓
                                             TowerResult
```

任何输入只在明确状态下生效，避免动画与点击竞争。

### 假物理原则

- 压缩形变用曲线映射，不直接依赖真实碰撞解算。
- 物品宽度可在高度下降时轻微增加，制造体积感。
- 碎片使用对象池和预设轨迹；不追求每次完全不同。
- 高塔在原型阶段可以先用预编排倒塌；正式版本根据垂直切片测试决定采用受限刚体还是多套可控倒塌编排。
- 只有当设计冻结后的正式可玩测试证明真实物理显著提升体验时才增加复杂度。

### 平台适配接口

```ts
interface PlatformAdapter {
  vibrate(kind: 'light' | 'medium' | 'heavy'): void;
  startRecording(): Promise<void>;
  stopRecording(): Promise<{ videoPath?: string }>;
  shareHighlight(payload: SharePayload): Promise<ShareResult>;
  showRewardedAd(placement: string): Promise<'rewarded' | 'skipped' | 'failed'>;
  onPause(handler: () => void): () => void;
  onResume(handler: () => void): () => void;
}
```

本地运行使用 `NoopPlatformAdapter`，保证没有抖音环境也能完整游玩。

## 9. 数据与验证

### 关键事件

- `game_first_interaction`
- `tutorial_press_completed`
- `item_press_started`
- `item_press_resolved`：物品、结果、压缩率、持续时间
- `combo_changed`
- `level_completed`
- `tower_smashed`
- `highlight_previewed`
- `share_clicked`
- `share_completed`
- `rewarded_ad_started/completed`

### 内部验证目标

以下是立项阶段的产品门槛，不是行业基准：

- 新玩家 5 秒内能在无人解释时完成第一次按压。
- 第一次有效爽点在启动后 10 秒内出现。
- 5 名测试者中至少 4 名愿意主动再压一件物品。
- 至少 3 名能通过形变而非只盯压力条完成合格判定。
- 30 秒灰盒演示在静音下也能被旁观者理解。
- 小规模测试的第二关主动开始率目标为 45% 以上。
- 测试者能够不经说明找到图鉴、模式切换和设置等主要界面。
- 完整UI的关键流程不存在死路、误触高发区或风格断层。

### 核心感觉闸门

正式30秒闭环完成后必须复盘：如果关闭奖励和成长后，连续压10件物品仍不有趣，暂停内容制作，优先重做按压曲线、结果反差和声音；不能用更多关卡掩盖核心无趣。交互反馈调整后需要同步更新Figma动效与状态说明。

## 10. 商业化边界

原型阶段先预留接口，不在核心感觉与完整UI流程验证前接入广告。正式版本可以包含克制的激励广告与自然关卡间隔，但商业化不能破坏连续按压节奏。

适合的激励点：

- 本关增加一个“神秘物品”。
- 结算时获得双倍图鉴材料。
- 体验一局特殊液压机皮肤。
- 对精彩视频进行额外特效包装。

不采用：强制打断连续按压的插屏、失败后制造焦虑的倒计时、必须看广告才能继续基础关卡。

## 11. 风险与应对

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 按压缺乏爽感 | 测试者只玩一次 | 优先改曲线、停顿、音效和反差，不加新系统 |
| AI 美术不一致 | 同屏物品像来自不同游戏 | 固定风格参考、轮廓、光向、视角和调色流程，并在 Figma 中统一构图 |
| UI看起来像原型 | 功能齐全但没有品牌感和层级 | 先完成Figma设计系统与全流程高保真稿，再进入Cocos正式实现 |
| 内容生产拖垮 OPC | 每件物品需要专属代码 | 限制为五种原型，所有差异配置化 |
| 视频不好看 | 过程节奏平，没有结尾 | 自动挑选事故/完美片段并保证倒塔高潮 |
| 低端机掉帧 | 粒子与碎片堆积 | 对象池、数量上限、30/60 FPS 分档 |
| 平台接入拖慢开发 | 核心代码直接调用 `tt.*` | 平台适配层与本地空实现 |
| 范围膨胀 | 设计阶段临时增加未定义系统 | 锁定24类界面和永久排除项，新增范围必须先改产品规划 |

## 12. 立项决策

目前视为已决定：

- 使用 Cocos Creator 3.8.7+ 与 TypeScript。
- 采用竖屏 2D 和视觉假物理。
- 完整 v1.0 包含 5 个主题、75 关、至少 50 件物品和 4 种游戏模式。
- 首发先验证 Android 抖音小游戏。
- Figma完整设计冻结是所有Cocos任务的硬前置。
- 首个正式可玩闭环使用3件物品，但采用已冻结的正式界面和视觉资产。
- 正式 UI 遵循“gpt-image-2 → Figma MCP → Cocos 1:1 实现”的固定流程。
- 无玩法服务端、无排行榜、无公会、无家园、无剧情、无多人、无自由文本。

暂不决定：

- 最终中文名与商标可用性。
- 具体广告频率。
- 是否加入真实刚体高塔。
- iOS 首发范围。
- 正式字体、音效库及授权来源。
