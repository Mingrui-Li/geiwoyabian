# 精简开发工作流

## 核心原则

这是单人开发的抖音小游戏，不采用大型团队的任务拆分和审阅流程。仓库只保留能让下一次对话继续工作的最少信息。

- 一个工作流可以跨多个对话持续进行，不要求一个对话完成一个任务。
- 不为单个组件、页面、状态、截图或检查项创建新任务。
- 不设置独立审阅/集成窗口；执行窗口对结果负责。
- 检查与风险成比例。除非定位真实问题，不重复制作台账、哈希证明和逐节点审计。
- 评价标准是玩家能看到和使用的成品，不是文档数量。

## 剩余路线

```text
GWP-017：一次性完成整套 Figma UI，并由用户确认
→ GWP-030：实现完整 Cocos 小游戏并完成发布验收
```

`GWP-018`至`GWP-026`以及`GWP-031`至`GWP-037`已取消，其内容分别并入上述两个工作流。

## 新对话如何继续

1. 阅读`AGENTS.md`、`docs/STATUS.md`和当前`IN_PROGRESS`工作流卡。
2. 查看Git状态和工作流卡末尾的一段进度记录。
3. 直接继续产出，不重新规划、不重新审计已经确认的内容。
4. 对话结束时更新一段简短进度；未完成就保持`IN_PROGRESS`。

## UI工作流完成标准

- Figma中已经能看到完整、统一、可开发的玩家界面，而不是组件展板。
- 启动/教学、主页与内容入口、游戏、暂停、结算、奖励及必要系统状态齐全。
- 核心流程和关键手机尺寸没有明显遮挡、裁切或不可读问题。
- 用户看过整体界面并确认可以进入开发。

## Cocos工作流完成标准

- 完整v1.0范围可玩，不以MVP或演示版收尾。
- UI遵循已批准Figma，核心压扁反馈有趣、清晰、解压。
- 完整内容、存档、抖音平台能力、性能、构建和发布检查在同一工作流内完成。

## Git与冲突

- 默认串行；同一时间只推进一个Figma写入或一个高度重叠的代码区域。
- 保留用户和其他窗口的未提交修改。
- 工作流达到阶段性可恢复点即可提交；只有完整工作流通过最终验收后才标记`DONE`。
