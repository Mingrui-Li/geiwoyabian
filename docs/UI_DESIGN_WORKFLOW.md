# UI/UX 与 Figma 工作流

## 1. 设计原则

UI 是《给我压扁！》完整体验的一部分，不是覆盖在玩法之上的功能壳。它需要延续液压机的重量感、软陶物品的亲和感和“把混乱变整齐”的满足感。

正式设计链路固定为：

```text
产品流程与信息架构
        ↓
gpt-image-2：风格探索、插画、纹理和装饰素材
        ↓
Figma MCP：设计系统、组件、完整屏幕、交互与适配
        ↓
设计评审和可点击原型验证
        ↓
Cocos Creator：依据精确节点与截图 1:1 实现
        ↓
真机截图与 Figma 基准逐屏视觉回归
```

Figma 是所有正式玩家界面的唯一设计源。生成图片不能直接充当完整界面，Cocos 场景也不能反向成为正式设计稿。

### 当前 Figma 工作区约束

- 唯一设计入口：[mini-game / node 11:7101](https://www.figma.com/design/83pqrCcig644vC20QXM5G1/mini-game?node-id=11-7101)。`11:7101` 是进入共享 Page 的定位锚点，不代表可以覆盖其相邻节点。
- 受当前 Figma 方案限制，本项目与其他项目共用同一个 Page，不新建独立 Page。所有本项目节点必须收纳在顶层 Section `GWP_给我压扁` 内，并保持清晰的命名前缀，禁止移动、重命名或覆盖 Section 外节点。
- 当前 Codex 环境优先使用已安装的 `figma-mcp-rust` 访问该文件，避免依赖官方 Figma MCP 的免费调用额度；任何写入仍须先加载对应 Figma 写入技能，并先检查目标节点和编辑所有权。

## 3. Figma 单 Page 结构

由于本项目只能与其他项目共用一个 Page，下列结构必须实现为 `GWP_给我压扁` Section 内的一级 Frame，而不是多个 Figma Page：

```text
00_Cover
01_Foundations
02_Components
03_User_Flows
04_Core_Screens
05_Modes_And_Collection
06_Overlays_And_States
07_Prototype
08_Dev_Handoff
99_Archive
```

- `GWP_给我压扁`：本项目唯一顶层 Section；上述 Frame、组件、流程和交付节点全部位于其中。
- `Foundations`：颜色、字体、字号、行高、间距、圆角、描边、阴影、透明度、层级和动效时长。
- `Components`：所有复用组件与变体，禁止复制后各自修改。
- `User_Flows`：首次体验、闯关、自由解压、今日订单、图鉴和分享流程。
- `Dev_Handoff`：只放已经评审通过、允许实现的精确版本。
- `Archive`：保存被替换方案，避免旧稿混入开发。

## 4. 设计基准与适配

### 画板

- 主设计基准：360×800。
- 验证画板：375×812、393×873。
- 最窄可用宽度按 320 设计像素检查。
- 顶部需避开抖音胶囊与设备状态区，底部需考虑系统手势区。

### 约束

- 关键操作使用底部拇指舒适区，但长按压扁操作区必须覆盖屏幕中下部的大面积空白区域。
- HUD 采用安全区锚定，不以绝对坐标锁死。
- 物品、压头和高塔是视觉主角，任何面板都不得长期覆盖中心舞台。
- 弹窗宽度响应屏幕但设最大值；正文区域可增长，按钮区域保持稳定。
- 所有触控热区不少于 44×44 逻辑设计单位（@2x 资产对应 88×88 像素），图标本身可以更小。

## 5. 设计系统

### 必须建立的变量

- 语义颜色：`brand`、`accent`、`success`、`warning`、`danger`、`surface`、`textPrimary`、`textSecondary`、`disabled`。
- 字体层级：展示标题、页面标题、卡片标题、正文、说明、数字强调、微型标签。
- 间距：4、8、12、16、24、32、48。
- 圆角：8、12、20、28、胶囊。
- 动效：快速点击、常规切换、奖励弹性、重击停顿。
- 层级：背景、机器、物品、效果、HUD、遮罩、弹窗、系统提示。

### 核心组件

- 主按钮、次按钮、图标按钮、危险/取消按钮
- 顶部资源胶囊、关卡卡片、主题卡片、模式卡片
- 压力条、关卡进度、连击徽章、星级结果
- 底部导航、分页切换、筛选标签
- 图鉴格子、物品详情卡、外观选择卡
- 通用弹窗、奖励弹窗、加载、Toast 和错误提示

所有交互组件至少包含：默认、按下、禁用、选中；按实际需要增加锁定、已完成、红点、加载和错误状态。

## 6. gpt-image-2 的职责

适合生成：

- 液压机、传送带、背景和主题装饰
- 可压物品、图鉴插画、空状态插画
- 面板材质、按钮质感、粒子母题和奖励图标草案
- 启动画面和分享预览中的关键插画

不直接采用：

- 带文字的完整界面截图
- 需要精确对齐的按钮组、列表和导航
- 数字、角标、品牌标识和小尺寸功能图标
- 未经 Figma 适配验证的整屏构图

每批生成素材先经过筛选、去字、透明边缘清理和统一调色，再放入 Figma。最终是否采用由屏幕中的实际效果决定，不以原始大图是否漂亮决定。

## 7. Figma MCP 设计阶段

1. 建立 Foundations 和组件变量。
2. 用 Auto Layout 组装低保真结构，先验证信息层级和流程。
3. 导入生成素材，完成高保真核心屏幕。
4. 建立完整组件变体，不用多个散落图层模拟状态。
5. 建立可点击原型，实际走通首次体验、闯关、图鉴和分享。
6. 对三个目标画板尺寸进行适配检查。
7. 将评审通过的精确节点移入 `Dev_Handoff`。

如果需要通过 Figma MCP 对文件写入，调用前必须先加载对应的 Figma 写入技能，并按照增量、小批次的方式创建和校验节点。

## 8. Figma 到 Cocos 的实现协议

每个屏幕或组件都按以下顺序实现：

1. 使用精确 Figma 节点链接获取 `get_design_context`。
2. 如果结构过大或响应截断，先获取 metadata，再缩小到需要的节点。
3. 获取同一节点的 Figma screenshot，作为视觉基准。
4. 同时拥有结构信息和截图后，才下载资产并开始 Cocos 实现。
5. 将 Figma 的布局、变量和组件语义翻译为 Cocos Widget、Layout、Sprite、Label 和 Animation；不照搬与引擎无关的代码表示。
6. 使用 Figma 提供的资产，不随意引入新的图标包或临时占位图。
7. 在目标画板比例和真机上截图，与 Figma 基准逐屏比较后修正。

## 9. 动效规范

Figma 负责定义状态变化和节奏，Cocos负责实现最终动画：

- 点击：轻微下压和回弹，反馈在 100ms 内开始。
- 页面切换：保持方向一致，不同时混用缩放、滑动和淡入。
- 解锁/奖励：允许更明显的弹性和粒子，但不超过主要玩法高潮。
- 完美判定：瞬时停顿、冲击扩散和数字落位需要同步。
- 弹窗：遮罩先出现，面板随后进入；关闭顺序相反。
- 减少动态效果设置开启时，应削弱震屏、弹性和持续漂浮。

## 10. UI 完成定义

一个屏幕只有同时满足以下条件才算完成：

- [ ] 信息架构和主要操作通过可点击原型验证
- [ ] Figma 中存在正式高保真节点和全部需要的状态
- [ ] 颜色、字体、间距和圆角来自设计变量
- [ ] 适配三个目标竖屏尺寸并处理安全区
- [ ] Cocos 实现使用正式资产且交互完整
- [ ] 真机触控热区、文字可读性和动画节奏通过检查
- [ ] Cocos 截图与 Figma screenshot 完成逐屏对照
- [ ] 加载、空、错误、锁定和恢复等适用边界状态已覆盖

## 11. UI 评审闸门

### 核心视觉评审

检查启动、主入口、游戏HUD、高塔结算和关卡结果，确认品牌感与玩法感一致后再扩展全量页面。

### 全流程评审

检查24个屏幕及其边界状态，确认无死路、无优先级混乱、无小热区、无样式漂移后再批量进入Cocos。

### 上线视觉回归

以 `Dev_Handoff` 为基准在真机逐屏对照。任何“以后再调”的明显偏差都视为未完成，不进入上线候选版本。
