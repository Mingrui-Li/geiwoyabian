# Figma UI设计工作流

## 目标

把《给我压扁！》完整玩家界面一次性设计完，然后进入Cocos开发。现有视觉基准、变量和组件直接复用，不再继续搭建“为了设计系统而设计系统”的内容。

## 工具与边界

- 视觉方向固定为B“充气贴纸工坊”。需要新插画时使用gpt-image-2。
- Figma查询和写入只使用`figma-mcp-rust`及仓库内`docs/figma/tooling/figma-mcp-rust-gwp014/`插件，禁止官方Figma MCP。
- 只编辑共享Page中的`GWP_给我压扁` Section，保护Section外节点。
- Cocos只在整套UI得到用户确认后开始。

## 本轮直接完成的界面

在Figma中直接组装玩家会使用的完整界面：

- 启动与首次按压教学。
- 主入口，以及闯关、模式、图鉴、外观、成就和设置入口。
- 主题/关卡/物品选择。
- 游戏主界面、压力反馈、暂停和连续游玩。
- 高塔粉碎、结算、奖励、解锁和下一局。
- 分享、广告确认、加载、断网、错误及必要确认弹窗。

可以合并视图和状态，不要求把旧24类规格机械做成24张独立画板。

## 工作方式

1. 直接使用现有组件组装完整页面。
2. 以整体界面和核心流程为单位检查视觉与操作问题。
3. 发现缺少组件时就地补齐，不另开任务。
4. 用关键屏幕验证常见竖屏尺寸，不为每张页面复制三套审计任务。
5. 输出一张整体总览和核心页面链接给用户确认；确认后整理最少的Cocos交接信息。

## 完成标准

- Figma中可直观看到完整游戏，而不是只有组件、变量和说明画板。
- 核心页面达到可直接照着开发的视觉质量，无明显占位、裁切、遮挡或流程死路。
- 视觉统一、按钮清晰、长按游戏区域不被HUD干扰。
- 用户明确确认整套UI可以进入Cocos开发。

不再要求逐节点metadata清单、每个组件单独截图、重复SHA校验、单独线框任务、单独响应式任务、单独审计任务或单独Dev Handoff任务。
