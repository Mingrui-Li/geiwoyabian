# GWP-014：Figma变量、样式与Foundations

## 目标

先建立完整变量、字体和效果样式，再建立Foundation文档结构，为所有后续组件提供唯一token来源。

## 必须使用的技能

- `figma-use`
- `figma-generate-library`

必须读取token creation、documentation creation、字体和效果样式相关参考。

## Figma执行前置

- 所有Figma查询与写入统一使用已安装的`figma-mcp-rust`；禁止调用官方Figma MCP。
- 创建第一个变量前必须重新列出`figma-mcp-rust`工具能力并验证能够设置variable scope与code syntax。当前0.2.0工具清单没有暴露这两个独立写入接口；必须先升级、扩展或找到经实测可验证的同工具链方案，否则停止任务，不能创建一批缺少scope/code syntax的变量后声称验收通过。
- v1不依赖远程design library；使用`figma-mcp-rust`检查本地变量、样式和组件，保护Section外节点。

## 交付物

- [ ] Primitive与Semantic变量集合、模式和alias关系
- [ ] 每个变量明确scope，禁止`ALL_SCOPES`
- [ ] 每个变量设置适用于后续Cocos映射的code syntax
- [ ] 颜色、间距、圆角、描边、透明度、层级和动效时长token
- [ ] 验证可用字体后建立文字层级与text styles
- [ ] 建立阴影、重击高光等effect styles
- [ ] 在单Page Section内建立Cover、Getting Started、Foundations、Components、Flows、Screens、Dev Handoff一级Frame
- [ ] Foundations颜色、字体、间距、圆角、阴影和动效说明画板
- [ ] 更新STATE.json的全部collection、variable、style和frame ID

## 验收

- [ ] 变量数量、集合、模式、scope和code syntax汇总完整
- [ ] 无重复raw value进入semantic层
- [ ] Foundations每个区域完成metadata与独立截图验证
- [ ] 字体名称经过available fonts检查，不凭记忆猜测
- [ ] 所有写入调用返回创建/修改节点ID并同步台账
- [ ] `git diff --check`通过

- 不修改Cocos工程
