# GWP-010：锁定完整UI体验规格

## 目标

在生成视觉素材或写入Figma前，给24类正式屏幕提供不可歧义的内容、动作、状态、文案和流程输入，消除“设计时再想”的空白。

## 必须使用的输入

- `docs/PROJECT_PLAN.md`
- `docs/UI_DESIGN_WORKFLOW.md`
- `docs/ROADMAP.md`的D0/D1/D2/D3/D4

## 交付物

- [ ] `docs/design/SCREEN_SPEC.md`：24类屏幕逐一描述目标、信息层级、主要动作、次要动作、入口和出口
- [ ] `docs/design/STATE_MATRIX.md`：每屏适用的默认、加载、空、锁定、完成、错误、断网和恢复状态
- [ ] `docs/design/USER_FLOWS.md`：首次体验、闯关、自由解压、今日订单、连续压、图鉴、外观和分享完整路径
- [ ] `docs/design/UI_COPY.md`：所有核心按钮、标题、说明、错误和奖励真实中文文案
- [ ] `docs/design/COMPONENT_INVENTORY.md`：按原子、内容、游戏专用分类的组件与变体清单
- [ ] `docs/design/ASSET_REQUIREMENTS.md`：gpt-image-2需要生成的场景、物品、纹理、插画和装饰清单
- [ ] 标明360×800、375×812、393×873的适配要求和44×44逻辑触控热区
- [ ] 用户审阅并确认屏幕范围、主导航和核心流程

## 验收

- [ ] 24类屏幕全部有具体内容，不使用“待定”“以后补”等占位语
- [ ] 每个流程都有开始、成功、取消、失败和返回路径
- [ ] 每个界面元素能映射到组件清单或资产清单
- [ ] HUD不遮挡物品、压头、高塔或主要手指区域
- [ ] 用户明确确认后才可将任务置为REVIEW
- [ ] `git diff --check`通过

- 不写入Figma
- 不初始化或修改Cocos工程
