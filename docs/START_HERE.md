# 新窗口从这里开始

本文件是任何新窗口、新对话和接手开发者的唯一入口。不要依赖旧聊天记录决定下一步。

## 1. 固定启动顺序

每个新对话必须按顺序完成：

1. 阅读根目录 `AGENTS.md`。
2. 阅读本文件。
3. 阅读 `docs/STATUS.md`，确认当前阶段、下一个动作和是否允许并行。
4. 阅读 `docs/PROJECT_PLAN.md` 中与任务相关的产品范围。
5. 阅读 `docs/ROADMAP.md` 中当前阶段的验收闸门。
6. 阅读准备认领的 `docs/tasks/GWP-xxx.md`。
7. 运行 `git status --short --branch` 和 `git log -5 --oneline`，核对文件事实与文档状态。
8. 只有任务状态为 `READY` 且依赖均为 `DONE` 时才开始工作。

如果聊天记忆、状态看板、任务卡和仓库事实不一致，停止编码；当前执行窗口先核实仓库与真实环境、修正文档，无法安全判断时再请求用户决定。

## 2. 当前应做什么

以 `docs/STATUS.md` 的“下一动作”为准。不要自行从路线图挑一个感兴趣的功能，也不要跨过当前阶段验收闸门。

当前项目采用设计先行硬门禁：`GWP-026` Figma设计冻结未`DONE`前，任何Cocos初始化、灰盒、玩法或正式UI任务都不能开始或合入。看到旧的`GWP-001`至`GWP-008`时应将其视为已取消历史，不得重新认领。

任务状态定义：

- `BLOCKED`：依赖或外部条件未满足，不能开始。
- `READY`：依赖已满足，可以认领。
- `IN_PROGRESS`：已有窗口认领，其他窗口不得重复开发。
- `DONE`：执行窗口已完成实现、独立验收、主线集成和状态同步。
- `CANCELLED`：任务不再执行，必须注明原因。

## 3. 如何认领任务

认领前先确认没有别的窗口正在修改同一任务或同一编辑范围，然后在任务卡中更新：

```yaml
status: IN_PROGRESS
owner: window-<简短名称>
started_at: YYYY-MM-DD
branch: codex/gwp-xxx-short-name
```

认领操作更新自己的任务卡；需要展示当前活跃任务时同步`docs/STATUS.md`。并行任务不得同时修改`docs/STATUS.md`、`docs/ROADMAP.md`或其他公共看板，完成者应先同步`main`再更新。

## 4. 开发完成后必须留下什么

在任务卡的“完成记录”中写明：

- 实际完成的内容。
- 重要文件和模块。
- 执行过的验证及结果。
- 未完成项、已知风险和后续建议。
- 是否产生新决策；若有，写入 `docs/DECISIONS.md` 并同步产品/技术文档。

同一个执行窗口必须逐项完成验收、修复发现的问题、把自己的任务分支集成到`main`，随后将任务直接置为`DONE`，把紧邻后续任务解锁为`READY`，并更新`docs/STATUS.md`。不再另开审阅集成对话。

## 5. 新对话的最短提示词

以后打开新窗口，只需发送：

> 请先完整阅读 AGENTS.md 和 docs/START_HERE.md，再根据 docs/STATUS.md 认领并执行下一项 READY 任务。不要跳阶段，也不要覆盖其他窗口的改动。

若希望指定任务，可发送：

> 请按仓库协作协议执行 GWP-xxx；先核对其状态、依赖和编辑范围，完成后更新任务卡并留下完整交接记录。

## 6. 绝对禁止

- 不读任务卡就直接编码。
- 两个窗口同时认领同一任务。
- 在共享工作树中并行修改重叠文件。
- 执行窗口合并不属于自己且未经用户明确指定的任务分支。
- 因为阶段任务较小而把完整 v1.0 降级成 MVP。
- 跳过 gpt-image-2、Figma MCP 或 Figma/Cocos 视觉对照直接完成正式 UI。
