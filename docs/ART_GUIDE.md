# 美术与素材生产规范

目标是通过“gpt-image-2 → Figma MCP → Cocos Creator”的完整设计链路，产出一致、精致且可准确实现的正式游戏视觉。gpt-image-2负责插画与质感素材，Figma负责设计系统、界面构图、交互状态和适配规范，Cocos负责忠实实现；三者不能互相替代。

## 1. 风格基线

### 关键词

软陶玩具、圆润工业设计、夸张材质、正面略俯视、粗轮廓、柔和阴影、明亮背景、幽默而不幼稚。

### 固定规则

- 所有可压物品使用相同的 3/4 正面视角和右上方主光源。
- 轮廓使用深墨蓝而不是纯黑。
- 单物品图不带地面、文字、标签、水印或复杂投影。
- 默认物品完整、居中，四周保留至少 12% 透明安全区。
- 游戏文字全部由引擎生成。
- 不直接采用模型生成的按钮文字、数字或品牌标识。
- 避免真实品牌、真实 App 图标、名人形象和受保护角色。

## 2. 色彩

| 用途 | 色值 |
|---|---|
| 工业主色 | `#FFC83D` |
| 压力与警告 | `#FF5D55` |
| 深色轮廓 | `#243145` |
| 成功与清爽 | `#63D7B0` |
| 背景奶油色 | `#FFF4DE` |
| 高光 | `#FFFFFF` |

生成资产允许有局部变化，但最终应通过统一调色靠近这套色板。

## 3. 首批正式设计资产

### 核心手感灰盒通过后生成

- 液压机：机架、压头、底座、警示灯四个可独立运动层
- 传送带：可横向平铺的主体与滚轮
- 背景：一张简化车间背景
- 首批 6 件物品：每件一个完整主图
- 通用裂纹遮罩 3 张
- 通用喷溅序列 1 套
- 通用碎片 8–12 个
- UI 视觉母题：面板材质、按钮质感、图标风格、进度条和装饰零件，随后在 Figma 中完成组件化

不要为每件物品生成完整受压动画。正式版本仍通过运行时缩放、遮罩、叠层与通用效果完成，但所有关键状态的视觉目标需要先在 Figma 中呈现。

## 4. 图片生成流程

1. 先生成一张包含液压机、三件示例物品和 UI 色板的风格基准图。
2. 人工选择唯一基准，不混用多套风格。
3. 之后每次只生成同一类别的 4–6 个物品，并始终附带基准图。
4. 逐个移除背景、品牌与错误文字。
5. 统一画布、视角、轮廓粗细、光向和颜色。
6. 将筛选后的资产导入 Figma，完成组件、页面和完整流程设计。
7. 在 Figma 的目标手机画板中验证实际尺寸；缩到手机屏幕上仍应一眼可辨。
8. 设计评审通过后，从精确 Figma 节点导出 Cocos 素材。
9. 最后再打图集和压缩，原始图保留在源素材目录之外。

## 5. 提示词模板

```text
为一款竖屏休闲解压小游戏绘制一个【物品名称】游戏素材。
风格：圆润软陶玩具，轻微夸张，粗而干净的深墨蓝轮廓，明亮高饱和配色，柔和塑料质感。
视角：固定 3/4 正面略俯视，主光从右上方照射。
构图：单个完整物体严格居中，四周保留 12% 安全区，无裁切。
输出：透明背景，无地面，无文字，无数字，无品牌，无水印，无额外物件。
它需要在手机屏幕上缩小显示时仍有清晰轮廓，并适合被垂直压扁的动画。
参考色：#FFC83D、#FF5D55、#243145、#63D7B0、#FFF4DE。
```

针对材质补充一句：

- 脆性：“外壳有清晰分块，方便叠加裂纹与碎片效果。”
- 弹性：“轮廓饱满，表面柔软，受压时适合横向膨胀。”
- 爆浆：“包含容易鼓起的软包装结构，但当前保持完整未破裂。”
- 嵌套：“具有能被压开的盖子或包装接缝。”

## 6. 输出规格

- 源文件：建议 1024×1024 PNG，透明背景。
- 游戏内大物品：最长边通常 512 px；小物品可降至 256 px。
- UI 小图标：源文件 256 px，进入项目后按显示尺寸评估压缩。
- 背景按目标竖屏比例生成，但将装饰与机器拆层，便于适配不同屏幕。
- 文件名使用小写英文与下划线，例如 `item_alarm_clock.png`。

建议目录：

```text
art_source/                 # 原始生成图，不进入游戏构建
assets/game/art/items/      # 清理后的物品图
assets/game/art/machine/    # 液压机与传送带
assets/game/art/effects/    # 裂纹、碎片、喷溅
assets/game/art/ui/         # UI 九宫格与图标
```

实际 Cocos 项目初始化时再创建目录；当前不要提交大量未经筛选的生成候选图。

## 7. Figma UI 设计要求

以下只是组件系统的基础，不是完整 UI 范围：

1. 主按钮：工业黄底、深色字，用于“开始”“继续”。
2. 次按钮：奶油色面板、深色描边，用于设置和返回。
3. 状态胶囊：显示连击、金币和进度。
4. 模态面板：结算与图鉴共用同一九宫格背景。

所有正式界面必须先在 Figma 中完成，并具备：颜色、字号、圆角、描边、阴影和间距变量；按钮与卡片的完整状态变体；Auto Layout；常见竖屏比例适配；可点击原型；开发标注。Cocos Creator 使用 Widget 与 Layout 复现这些约束，不允许跳过 Figma 直接凭感觉拼正式界面。完整流程见 `docs/UI_DESIGN_WORKFLOW.md`。

## 8. 美术验收清单

- [ ] 缩到实际手机尺寸仍能在一秒内认出物品
- [ ] 光源方向、视角和轮廓与基准图一致
- [ ] 没有生成文字、品牌、水印和多余零件
- [ ] 透明边缘干净，没有白边或背景残留
- [ ] 受压横向放大后不会暴露明显绘制错误
- [ ] 同屏资产的饱和度和黑位接近
- [ ] 文件尺寸与实际显示尺寸相称
- [ ] UI 文字不是图片的一部分
- [ ] 素材已在 Figma 目标画板中验证，而不是只查看原始大图
- [ ] Cocos 实现与 Figma 截图完成逐屏视觉对照
